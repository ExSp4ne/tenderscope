# TenderScope (ТендерСкан)

Сервис первичного автоматического аудита контрактов госзакупок (44-ФЗ и 223-ФЗ) для защиты малого бизнеса от кабальных условий.

Система принимает номер закупки из ЕИС или загруженные документы (PDF, DOCX) объемом до 150 страниц, находит скрытые юридические и финансовые риски, ранжирует их по принципу «светофора» и подтверждает каждый вывод дословной цитатой с указанием пункта и страницы договора.

---

## Что делает сервис

* **Выгрузка из ЕИС и парсинг файлов:** загружает проект контракта по регистрационному номеру или принимает локальные файлы PDF и DOCX, очищая текст и сохраняя номера страниц, разделов и пунктов.
* **Поиск ловушек по 5 категориям:**
  1. *Финансы и оплата:* скрытые отсрочки расчетов (60–90 рабочих дней вместо законных 7), привязка к лимитам бюджета.
  2. *Штрафы и пени:* несоразмерные санкции, расчет неустойки от всей цены контракта вместо просроченного этапа.
  3. *Скрытые требования:* лицензии, допуски СРО, требования к сертификации внутри текста договора.
  4. *Сроки и приемка:* затянутая экспертиза заказчика (до 45 дней), нереалистичные сроки исполнения.
  5. *Расторжение и гарантии:* односторонний отказ заказчика (риск попадания в РНП), блокировка обеспечения.
* **100% подтверждение цитатами:** каждая карточка риска содержит дословную цитату из текста, проверенную автоматической сверкой с исходником, и ссылку на страницу.
* **Наглядный светофор рисков:** деление условий на критические (красный), предупреждающие (желтый) и безопасные (зеленый) с фильтрацией в интерфейсе.
* **Экспорт отчета для руководителя:** генерация сводного PDF-документа со статистикой и таблицей рисков в один клик.

## Структура репозитория

Проект организован по схеме монорепозитория с изоляцией зон ответственности:

```text
tenderscope/
├── docs/                     # Архитектура, спецификации и форматы обмена данными (JSON)
│   ├── tech_spec.md          # Полное техническое задание проекта
│   └── contracts.md          # Контракты данных между сервисами
├── backend/                  # Серверная часть (API, БД, интеграции)
│   ├── core/                 # Жизненный цикл проверок, хранилище, история, фильтрация
│   ├── eis/                  # Модуль запросов в ЕИС, распаковка архивов закупки
│   └── pdf_export/           # Генератор итогового PDF-отчета для руководителя
├── analyzer_bridge/          # Конвейер подготовки текста и верификации цитат (Python)
│   ├── parser/               # Извлечение текста и таблиц из PDF/DOCX по страницам
│   ├── chunker/              # Нарезка договора на смысловые фрагменты по пунктам
│   └── verifier/             # Программная сверка цитат модели с исходным текстом
├── ml/                       # Аналитический контур (модели и правила выявления рисков)
│   ├── prompts/              # Инструкции и критерии поиска по 5 категориям
│   └── dataset/              # Эталонная выборка реальных контрактов для калибровки
├── frontend/                 # Пользовательский интерфейс (дашборд светофора, фильтры, карточки)
├── docker-compose.yml        # Конфигурация запуска сервисов в контейнерах
├── .env.example              # Шаблон переменных окружения
└── README.md
```

## Правила работы с Git (Branching Workflow)

Чтобы команда не конфликтовала при слиянии изменений, в репозитории действуют простые правила:

* **`main`** — только стабильные, проверенные версии для демонстраций. Прямые коммиты в `main` закрыты.
* **`dev`** — основная рабочая ветка интеграции. Все задачи вливаются сюда через Pull Request (Merge Request).
* **`feat/...`** — персональные ветки для задач каждого разработчика:
  * `feat/eis-downloader` — задачи Бэкендера 1;
  * `feat/checks-storage` — задачи Бэкендера 2;
  * `feat/text-chunker` — задачи Бэкенд/ML-разработчика;
  * `feat/risk-classifier` — задачи ML-разработчика;
  * `feat/traffic-light-ui` — задачи Фронтендера.
* **`fix/...`** — срочные исправления багов в ветке `dev`.

## Команда разработки

Проект реализуется в рамках студенческого проектного интенсива (срок — 7 недель):

* **Бэкенд-ML:** Конвейер чтения документов, нарезка текста, очередь задач и сверка цитат.
* **Бэкендер 1:** Интеграция с ЕИС, прием файлов, генерация PDF-отчетов.
* **Бэкендер 2:** Внутреннее ядро, хранилище данных, смена статусов, история проверок и фильтрация.
* **ML-разработчик:** Промпты и правила выявления 5 категорий рисков, классификация по «светофору».
* **Фронтендер:** Пользовательский интерфейс, пошаговый экран ожидания, дашборд результатов.
