# Проверка детектора рисков

Скрипт использует стандартную библиотеку Python и обращается к API Chat
Completions. По умолчанию ожидается запущенная локальная Ollama с моделью
`qwen2.5:7b`. Команды выполняются из каталога `ml/`.

```powershell
ollama pull qwen2.5:7b
python evaluate_sample.py
python evaluate_sample.py --runs 5
```

Для другого сервера укажите полный URL в `RISK_API_URL`, имя модели в
`RISK_MODEL` и при необходимости ключ в `RISK_API_KEY`. Скрипт проверяет
сырой текст ответа через `json.loads`, набор полей, `payment/red` и точное
совпадение цитаты с предложением из контрольного фрагмента. Код выхода
ненулевой при первом несоответствии. Контрольный фрагмент взят из примера
в `docs/contracts.md`.

## Эталонные документы

В `dataset/annotations.json` поле `pending_sources` содержит кандидатов,
для которых еще предстоит скачать или проверить первичный документ.
В `documents` добавляются только проверенные документы с полями `file`,
`law`, `source_url` и `annotations`. Каждая аннотация содержит `page`
(счет с единицы), `clause`, `exact_quote`, `category` и `level`.
Для DOCX сверяйте страницу в зафиксированном PDF-рендере оригинала.
Для контрольного документа без выявленных рисков указывайте пустой
массив `annotations` после проверки всех пяти категорий.

## Батч-прогон

Из `ml/` с активированным Python-окружением и запущенной моделью:

```powershell
python -m pip install -r ../analyzer_bridge/requirements.txt
python evaluate_dataset.py
python -m unittest test_batch_runner
```

Настройки `RISK_API_URL`, `RISK_MODEL` и `RISK_API_KEY` те же, что у
`evaluate_sample.py`. На сервер отправляются реальные фрагменты документов;
по умолчанию используется локальный сервер. Анализатор возвращает только
красные и жёлтые карточки, с исходными координатами и `chunk_index` (от нуля).
Невалидный JSON/формат повторяется один раз, затем чанк пропускается с
предупреждением в stderr. При недоступном API прогон останавливается с ошибкой.
После каждого обработанного чанка выводятся время, результат и накопленные
счётчики по документу. Метрики по эталонам выводятся после документа.
Карточки и метрики также сохраняются в `benchmark_results.md` после каждого
документа. В начале нового прогона этот локальный отчёт перезаписывается.

- `recall`: число найденных эталонов / число аннотаций. Нужны та же категория
  и уровень; обе цитаты должны быть в том же чанке после нормализации bridge.
  Цитата модели должна содержать эталон или составлять непрерывную часть
  не короче половины эталона. Одна карточка засчитывается не более одного раза.
- `false positives`: все возвращённые карточки на `05_safe_standard.docx`.
- `exact_quote (gold)`: число посимвольных совпадений с эталоном / все эталоны.
  `exact_quote (chunk)`: сколько цитат модели дословно присутствуют в своём
  чанке / все возвращённые карточки. Ни одна строгая проверка не нормализует
  пробелы и переносы. При пустом знаменателе выводится `n/a`.
